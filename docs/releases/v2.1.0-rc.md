# MoneyFlow v2.1.0 Release Candidate

Status: release candidate notes only. No tag created.

## 1. Summary

v2.1.0 candidate focuses on onboarding, app preferences, mobile/PWA readiness, and safe runtime diagnostics.

This wave prepares the product for better first-run guidance and later APK packaging without creating a native Android project yet.

## 2. Backend Changes

Endpoints:

- `GET /api/me/preferences`
- `PATCH /api/me/preferences`
- `GET /api/me/runtime-diagnostics`

Migration:

- `V24__user_preferences.sql`
  - Adds `user_preferences`.
  - Stores locale and onboarding flags per user.
  - Creates rows lazily when preferences are first read or patched.

Docs:

- `docs/mobile-apk-readiness.md`

Voice/audio:

- Current `dev` includes voice audio fixes for Cloudinary upload parameters, safer upload failure logging, stable playback states, and transcript-only handling.
- Old failed voice records remain failed; create a new voice record for live audio verification.

## 3. Frontend Changes

Expected frontend wave scope:

- Guided onboarding tour.
- i18n foundation for `vi` / `en`.
- Backend preference sync.
- Settings Hub.
- PWA install prompt / install help.
- GSAP animation polish.
- Mobile navigation, if already merged in the frontend `dev` branch.

Note: this backend repo does not verify frontend commit state. Confirm in the frontend repo before final release.

## 4. Manual UAT Checklist

Environment:

- [ ] Backend is running on the intended profile (`dev` for local, `production` only for deploy).
- [ ] Frontend API base URL points to the intended backend.
- [ ] Browser console has no P0 errors after backend and frontend are both started.
- [ ] Test account uses non-production financial data.

Auth and app shell:

- [ ] Login succeeds.
- [ ] Logout clears usable session.
- [ ] Dashboard loads after login.
- [ ] Workspace list loads.
- [ ] Route reload keeps the user on a valid screen.
- [ ] Transactions reload correctly.

Preferences and locale:

- [ ] `GET /api/me/preferences` returns defaults for a new user.
- [ ] `PATCH /api/me/preferences` persists partial updates.
- [ ] Locale `vi-VN` persists after reload.
- [ ] Locale `en-US` persists after reload.
- [ ] Invalid locale is rejected.

Onboarding:

- [ ] Welcome onboarding appears for a new user.
- [ ] Completing the tour prevents repeat on refresh.
- [ ] Skipping the tour prevents repeat on refresh.
- [ ] Replay tour works from Settings Hub.
- [ ] Reset onboarding state works if exposed in Settings Hub.
- [ ] Onboarding does not block daily use after completed/skipped.

Settings and diagnostics:

- [ ] Settings Hub opens.
- [ ] Runtime diagnostics page/action calls `GET /api/me/runtime-diagnostics`.
- [ ] Diagnostics show profile/root, DB readiness, and storage configuration booleans.
- [ ] Diagnostics do not show DB URL, JWT, Cloudinary API key, Cloudinary API secret, or user financial data.

PWA and mobile:

- [ ] PWA install banner or install help appears where supported.
- [ ] Browser that does not support install prompt shows clear help or no broken UI.
- [ ] 360 px layout has no horizontal scroll.
- [ ] 390 px layout has no horizontal scroll.
- [ ] 414 px layout has no horizontal scroll.
- [ ] Mobile bottom navigation is usable.
- [ ] Safe area / notch spacing is acceptable.

Voice:

- [ ] New voice record can be created.
- [ ] New voice audio upload succeeds when storage is configured.
- [ ] New voice audio playback succeeds.
- [ ] Transcript-only record does not show a fake playable button.
- [ ] Storage failed state is visible and does not hide the saved transaction.

Core finance flows:

- [ ] Transaction create/update/delete works.
- [ ] Daily Closing load/edit/complete works.
- [ ] Planning screen loads actual spendable data.
- [ ] Debts screen loads and basic actions work.
- [ ] Emergency fund screen loads and basic actions work.
- [ ] Sinking funds screen loads and basic actions work.
- [ ] Student loans screen loads and remains clearly simulation-only.

Accessibility / motion:

- [ ] Keyboard focus remains usable in onboarding/settings.
- [ ] Reduced-motion preference is respected or animations remain non-blocking.
- [ ] GSAP polish does not hide content or break route transitions.

## 5. Known Risks

- Cloudinary runtime must be verified manually in the deployed/runtime environment.
- Old failed voice records remain failed and should not be used as proof that the new upload path is broken.
- Root repo remote may be inaccessible; backend docs may be the pushed source of truth.
- PWA install availability varies by browser and platform.
- GSAP animations need reduced-motion checks.
- i18n is a partial foundation, not a full product translation.
- Mobile WebView microphone and file-picker behavior may differ from desktop Chrome.
- Service worker caching must be checked to avoid private financial API caching.

## 6. Go / No-Go Criteria

Go only if:

- [ ] No console P0 errors after backend and frontend are started correctly.
- [ ] No secret is exposed in runtime diagnostics.
- [ ] No private financial API response is cached by service worker.
- [ ] Onboarding is not repeated after completion or skip.
- [ ] New voice upload and playback are stable.
- [ ] Mobile nav is usable at 360 px, 390 px, and 414 px.
- [ ] Login/logout and dashboard load are stable.
- [ ] Preferences persist across refresh.

No-go if any item above fails.

## 7. Rollback Notes

- Frontend changes are mostly UI/preferences and can usually be rolled back at the frontend deployment layer.
- Backend migration adds `user_preferences`.
- Do not rollback the database casually after users create preferences.
- If onboarding or install UX causes problems, disable or hide the frontend entry points first.
- If needed, disable the PWA banner using localStorage/state until the frontend fix is deployed.
- Runtime diagnostics are authenticated and read-only. They can remain enabled unless a safety issue is found.
