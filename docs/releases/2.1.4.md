# MoneyFlow 2.1.4

Status: PLANNED / PARTIALLY IMPLEMENTED

Release target: backend Receipt OCR foundation.

## Boundary

2.1.4 is planned as a backend-first receipt OCR/image-to-draft release. P11C adds OCR provider abstraction and deterministic mock OCR only. It does not make real OCR production-ready and does not add receipt draft or confirm behavior.

## Planned Phases

| Phase | Status | Scope |
| --- | --- | --- |
| P11A | Complete when docs are merged | Receipt OCR current pipeline audit, backend contract, release plan. |
| P11B | Implemented | Receipt session/upload backend foundation. |
| P11C | Implemented | OCR provider abstraction + mock provider. |
| P11D | Planned | Azure Document Intelligence provider. |
| P11E | Planned | Receipt draft builder/parser. |
| P11F | Planned | Confirm executor + transaction evidence link. |
| P11G | Planned | Release lock and validation. |

## Non-Negotiables

- Receipt OCR is draft-first.
- OCR text/image are evidence, not final truth.
- No receipt OCR result auto-posts a transaction.
- Confirm is required before ledger mutation.
- Expense wallet/category rules are preserved.
- Storage failure does not block review/confirm when OCR/manual text can proceed.
- No fake OCR financial data in runtime paths.
- Workspace membership is required for all receipt session/draft access.

## P11B Implemented

- `POST /api/workspaces/{workspaceId}/receipt-sessions`
- `POST /api/workspaces/{workspaceId}/receipt-sessions/{sessionId}/image`
- `GET /api/workspaces/{workspaceId}/receipt-sessions/{sessionId}`
- `receipt_sessions` table.
- Receipt image metadata and storage status.
- Cloudinary receipt image storage support, disabled by default.
- No OCR, no draft builder, no confirm-to-transaction.

## P11C Implemented

- `POST /api/workspaces/{workspaceId}/receipt-sessions/{sessionId}/ocr`
- Provider modes: `none`, `mock`, `azure_document_intelligence` placeholder.
- Deterministic mock OCR by filename.
- OCR result persistence on receipt session.
- OCR text normalization.
- No draft builder, no confirm-to-transaction, no real Azure OCR yet.
