# MoneyFlow 2.1.6

Status: PLANNED / NOT IMPLEMENTED. P13A audit and contract only.

Release target: Planning Backend.

## Boundary

2.1.6 is a backend-first planning release. It should build toward upcoming obligations, reserves, projection, and actually-spendable planning APIs. P13A does not implement runtime features.

## Planned Scope

- Planning backend audit and contract.
- Planned obligation model/API foundation.
- Reserve allocation model/API foundation or safe reuse of existing reserve modules.
- Planning projection service.
- Mark-paid/link-to-transaction behavior.
- Planning overview API and action item integration.
- Backend release lock.

## Deferred Scope

- Frontend planning dashboard redesign.
- AI/LLM planning advice.
- Notifications and scheduled jobs.
- Automatic transaction posting from due dates.
- Fake expected income.
- Broad jar/category/debt redesign unless a later phase proves it necessary.

## Current Backend Evidence

- Existing planning API: `/api/workspaces/{workspaceId}/planning/actually-spendable`.
- Existing planning preferences API: `/planning/preferences`.
- Existing recurring obligations and occurrence confirmation APIs.
- Existing sinking fund, savings goal, and emergency fund reserve ledgers.
- Existing debt module with payable/receivable, due date, remaining amount, and payment history.
- Existing wallet balance service grounded in posted wallet-affecting transactions.
- Existing P12 Financial Insight spendable/action item patterns.

## Non-Negotiables

- Planned obligation does not affect wallet balance until paid as actual transaction.
- Reserve allocation does not create or destroy money.
- Expected income is not actually spendable.
- Receivable debt is not spendable until collected.
- Payable debt is not normal expense.
- Wallet snapshots remain reconciliation evidence.
- Drafts and fake data do not affect planning.
- Workspace isolation is required for every endpoint.

## Known Limitations

- Planning v1 contract is not implemented yet.
- No `/planning/overview` endpoint exists yet.
- Standalone payable debts are not included in the current planning formula.
- Current planning service subtracts recurring obligations but not overdue outflows separately.
- Reserve aggregates can overlap because cross-module deduplication is not inferred.
- No notification/scheduler exists.
- No frontend UI work is included in P13A.
